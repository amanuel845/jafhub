jafhub-full

A compact, interactive GitHub REST + GraphQL explorer designed to run as a Vercel serverless application. Supports both a shared server-side token and per-user client tokens, with strict header and path allowlisting.

RESTGraphQLVercelNode 20Server + client tokenRate telemetryMobile

Quick start

  1. Create a new GitHub repository and upload the project.
  2. Import the repository into Vercel.
  3. (Optional) set GITHUB_TOKEN and ALLOWED_ORIGINS in Vercel environment variables.
  4. Deploy.
  5. Open the playground. Choose Auth to enter a personal fine-grained PAT (overrides the server token for your requests), or leave it blank to use the server token / public access.
Local development: install dependencies then run npm run dev with the Vercel CLI.

Features

REST Explorer

GET, POST, PUT, PATCH, DELETE, HEAD against arbitrary GitHub REST paths.

GraphQL Explorer

Run GraphQL queries with JSON variables and inspect the response.

Dual auth

Server env token by default; per-user PAT override for the browser.

Rate & Usage

Observed limit, remaining, used and resource from GitHub headers.

Request History

Recent method, path, status and latency per session.

Developer tools

JSON formatter, raw/pretty toggle, copy, cURL generator.

Endpoint catalog

Core, repos, issues/PRs, search, orgs, Actions, gists, Git data, packages, security.

Custom paths

Any GitHub REST path can be typed directly.

Hardened proxy

Method allowlist, header allowlist, body caps, path traversal rejection, CORS allowlist.

Architecture

Browser
  │
  ├── /api/github/<path> ──► GitHub REST API
  ├── /api/graphql ─────────► GitHub GraphQL API
  └── /api/meta ────────────► Server info & auth mode
          │
          ▼
      GitHub response
          │
          ▼
     Playground UI

All traffic is same-origin. The browser never talks to api.github.com directly.

REST proxy

The catch-all route api/github/[...path].js maps:

GET /api/github/repos/OWNER/REPO/issues?state=open

to:

GET https://api.github.com/repos/OWNER/REPO/issues?state=open
MethodSupportedTypical use
GET✓Read, list, search.
POST✓Create resources, trigger actions.
PUT✓Replace/update operations.
PATCH✓Partial updates.
DELETE✓Delete supported resources.
HEAD✓Metadata only.

Body limit

REST requests are capped at 1 MB. Larger bodies receive 413.

GraphQL

Endpoint: POST /api/graphql. Body:

{
  "query": "query Viewer { viewer { login name } }",
  "variables": {},
  "operationName": "Viewer"
}

Body limit: 256 KB. Upstream target: https://api.github.com/graphql.

Meta

Endpoint: GET /api/meta. Returns server information useful to the frontend:

{
  "name": "jafhub-full",
  "version": "3.0.0",
  "upstream": "https://api.github.com",
  "githubApiVersion": "2022-11-28",
  "authMode": "server" | "public",
  "corsOrigins": [...],
  "capabilities": {
    "rest": true,
    "graphql": true,
    "serverToken": true,
    "clientTokenOverride": true
  }
}

Rate limits & usage

The Rate & Usage tab displays values observed directly from GitHub response headers. It does not compute a universal quota, because GitHub exposes different limits per resource bucket and per authentication mode.

Reminder: the session counter is a playground metric, not GitHub's remaining quota.

Authentication

The proxy resolves an Authorization header using this priority:

PrioritySourceMode reported
1Client Authorization: Bearer …client
2Server env GITHUB_TOKENserver
3Nonepublic

Every proxy response carries X-Playground-Auth-Mode so the caller can confirm which path was taken. The UI also shows the effective mode in the header bar.

Client tokens

Enter a GitHub fine-grained PAT via Auth. The UI stores it in localStorage and sends it as Authorization: Bearer github_pat_….

Server token

Set GITHUB_TOKEN in Vercel environment variables. Never commit it. When set, unauthenticated browser requests automatically use it.

Security

Browser storage warning: the playground stores a client-entered PAT in localStorage. Any JavaScript running on the same origin can read it. This is fine for a personal developer playground; not a hardened secret vault.
  • The proxy never forwards to arbitrary upstreams — the GitHub host is hardcoded.
  • Request headers are allowlisted.
  • Response headers are allowlisted.
  • Path segments are validated and encoded; .., ://, \0 are rejected.
  • HTTP methods are allowlisted.
  • Body size caps: 1 MB (REST), 256 KB (GraphQL).
  • CORS is off by default. Set ALLOWED_ORIGINS only when you need cross-origin access.
  • Use a fine-grained PAT with the minimum scope and a short expiration.

Vercel deployment

  2. Push the project files.
  3. Import the repository into Vercel.
  4. (Optional) set GITHUB_TOKEN and ALLOWED_ORIGINS.

Configuration

Target Node 20.x. Function size/time limits are declared in vercel.json:

{
  "functions": {
    "api/github/[...path].js": { "maxDuration": 60, "memory": 512 },
    "api/graphql.js":          { "maxDuration": 60, "memory": 512 },
    "api/meta.js":             { "maxDuration": 15, "memory": 256 }
  }
}
